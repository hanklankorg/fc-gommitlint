Gommitlint validates Git commit messages against a set of (configurable) rules.
For CLI-user, CI-pipe, Human or AI-agent, solo-devs or teams.

'''

* Out of the box validation based on best practices
* Simple to use and get started with, powerful features if you need them

== Quick Start

image::assets/gommitlint-onboarding.gif[Gommitlint onboarding demo,width=820]

Install with https://mise.jdx.dev/[mise]:

[source,bash]
----
mise use "forgejo:itiquette/gommitlint@<version>"
----

Packages (`.deb`, `.rpm`, `.apk`), BSD and macOS archives, the container image, and SHA-256 repository support are covered in link:{repo-base}/docs/modules/ROOT/pages/install.adoc[Install].

Then validate:

[source,bash]
----
# Validate last commit
gommitlint validate --ref HEAD --no-ci-detect

# Validate all commits in feature branch against main
gommitlint validate --base-branch=main

# Validate specific commit range
gommitlint validate --range=main..feature-branch --no-ci-detect
----

Choose one target mode. Without `--no-ci-detect`, a detected CI base can override an explicit range, ref, or count.

== Validation Rules

Gommitlint works out of the box with these rules; no configuration file is required.

[cols="1,1,3,^1",options="header"]
|===
| Rule ID | Display | Description | Default

| `branchahead` | Branch Ahead | Max commits ahead of an effective base branch, explicit or CI-detected (default limit: 10) | ✓
| `commitbody` | Commit body | Commit body requirements (presence, length, line width) | ✓
| `conventional` | Commit type | https://conventionalcommits.org[Conventional Commits] format | ✓
| `cryptosignature` | Signature | Signature presence, armor, type, and optional key-inventory policy | ✓
| `identity` | Identity | Allows commit author emails by exact address or domain wildcard |
| `jirareference` | JIRA reference | Requires JIRA ticket references |
| `linearhistory` | Linear History | Requires linear history (no merge commits) |
| `signoff` | Sign-off | Requires https://developercertificate.org/[Signed-off-by] trailer | ✓
| `spell` | Spelling | Spell checking | ✓
| `subject` | Subject | Subject line length (default: max 100) and format | ✓
|===

Each failure also carries a stable `GLxxx` check ID; see link:{repo-base}/docs/modules/ROOT/pages/reference/rules.adoc[Validation Rules] for the catalog and link:{repo-base}/docs/modules/ROOT/pages/reference/configuration.adoc[Configuration] for enabling, disabling, and tuning rules.
